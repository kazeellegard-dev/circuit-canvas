## 失敗の詳細

### C1（重大）: インスペクタの「メモを削除」でアプリがクラッシュする

- 再現手順（2回とも再現。2回目は、アプリを再起動した直後の初期状態から、編集なしで実施）:
  1. 選択ツールのまま、付箋「R12を変更」をタップして選択する。
  2. 右上の「確認」を押す（インスペクタが開く）。
  3. 「メモを削除」を押す。
- 実際の挙動: アプリが即座に終了し、ホーム画面へ戻る。
- 期待する挙動: 付箋がキャンバスから消え、インスペクタが図面の概要表示に戻り、選択が解除される。
- 証跡:
  - `selection-inspector-2026-09-21-after-note-delete-crash.png`（クラッシュ後のホーム画面）
  - `selection-inspector-crash-2026-09-21.ips`（クラッシュレポート）
- クラッシュの内容（`.ips` から）: `EXC_BREAKPOINT (SIGTRAP)`、`Fatal error: Index out of range`（`Swift/ContiguousArrayBuffer.swift:692`）。
- スタックの要点: `Toggle.init(toggledOn:label:)` → `ToggleState.stateFor` → `Binding.readValue` → `Binding<A>.subscript.getter` → `Array.subscript.read`。
- 原因の推測（未検証）: `ContentView.swift` の `inspector` で、付箋の `Toggle("完了", isOn: $notes[index].complete)`（および `Picker` / `TextField` の `$notes[index]...`）が、削除前に取得した `index` を保持している。`notes.remove(at: index)` の直後、`selectedNote = nil` による再描画の前に、`Toggle` がその `index` で `notes` を読み、範囲外になる。
- 修正方針の案:
  - `index` を使わない Binding にする（例: `id` から要素を探す `Binding(get: { notes.first { $0.id == id }?.complete ?? false }, set: { ... })`）。
  - または、付箋の編集部分を別ビュー（`NoteInspector(note: Binding<NoteItem>)`）に切り出し、削除は親側で `notes.removeAll { $0.id == id }` と `selectedNote = nil` を行う。
- 関連する潜在リスク: シンボル側も同じ `$symbols[index].title` のパターン。今回の削除ではクラッシュしなかったが、名称欄にフォーカスがある状態などで同様に落ちる可能性がある（未確認）。
- 受け入れ条件: 付箋・シンボルのどちらも、インスペクタから何度削除してもクラッシュしない。削除後に選択が解除され、インスペクタが概要表示になる。

## 成功しても残る問題

### S1: シンボルを削除すると、接続されていた配線が孤立して残る

- 再現手順: Temperature をタップして選択 → 「確認」→「シンボルを削除」→ シートを閉じる。
- 実際の挙動:
  - シンボルは消えるが、Temperature に接続されていた配線は、端点がピンから離れた状態で描画されたまま残る（MCU の左側から下へ伸びる線と、途中で止まる横線）。
  - インスペクタの「接続済み配線」は、削除後も 3 のまま。
- 期待する挙動（推測）: そのシンボルに接続された配線も一緒に削除される（または、少なくとも接続数に反映される）。仕様が未定なら、要確認。
- スクリーンショット: 残っている画面は、テスト時にのみ取得（このフォルダには保存していない）。

## 成功項目の詳細

### 1. シンボルの選択

- 選択ツールで Main MCU をタップすると、青い太枠で強調表示された。
- タップしただけで、キャンバスはパンしなかった。

### 2. シンボル名称の編集

- 「確認」でインスペクタが開き、選択中のシンボル用に「名称」「接続（接続あり）」「シンボルを削除」が表示された。
- 名称欄に追記すると、シートの上部と、キャンバス上のシンボルが即座に更新された（例: `Main MCU` → `Main MCU v 2`。日本語IMEの候補が全角スペース入りだっただけで、アプリの不具合ではない）。

### 3. 付箋の編集

- 付箋をタップすると青枠で選択され、シンボルの選択は解除された。
- インスペクタは「実験メモ」の表示に切り替わり、「種別・タイトル・本文・完了・関連付けを開始・メモを削除」が表示された。
- タイトルへの追記、本文への追記、「完了」のオンが、すべてキャンバスの付箋に反映された（完了時はグレー表示にチェックアイコン）。

### 4. ドラッグ

| 対象 | 操作 | 結果 |
|---|---|---|
| CAN シンボル | 下へ100pt | +165px＝100pt。接続配線が追従 |
| 付箋 | 右へ100pt | +165px＝100pt。引出し線が追従 |
| Temperature | 右へ3pt | 移動せず、選択のみ（タップ扱い） |
| Temperature | 右へ10pt | +16.5px＝10pt 移動（しきい値の4ptぶんが失われない） |

- ドラッグしても、キャンバス全体はパンしなかった。
- シンボルをドラッグしても、そのシンボルは選択されない（直前の選択は変わらない）。仕様として問題なければ対応不要。

### 5. タップ時のパン

- シンボル、付箋のタップで、キャンバス全体は動かなかった（タップ前後で他の要素の位置が同じ）。

### 6a. シンボル削除

- インスペクタから削除すると、キャンバスからシンボルが消え、インスペクタが概要表示（シンボル 3 / 未完了メモ 0 / 接続済み配線 3）に戻り、選択が解除された。
