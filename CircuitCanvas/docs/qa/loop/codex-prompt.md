# Codex への指示（自動ループ用・固定部分）

あなたは iPad SwiftUI アプリ CircuitCanvas の実装担当です。この指示の後ろに「タスク」と、あれば「前回の QA 失敗」が続きます。

## やること

1. 「前回の QA 失敗」がある場合は、それをすべて修正する（なければ「タスク」を実装する）。
2. 修正した失敗 1 件につき、再発を検知する UI テストまたはユニットテストを 1 つ以上追加する（`CircuitCanvasUITests` / `CircuitCanvasTests`）。
3. 可能なら `xcodebuild test` で自分でも確認する。サンドボックスの制約で実行できなくても構わない（ループ側が、コミット後に同じゲートを必ず実行する）。
4. `CircuitCanvas/docs/qa/<タスク名>-handoff-YYYY-MM-DD.md` を作る。内容は次の 4 点:
   - 変更したファイル一覧（コミットハッシュはループ側が付けるため不要）
   - 変更内容と、失敗があった場合はその原因
   - QA 担当（Claude Code）向けの確認手順（項目ごとに期待する結果）
   - 自分で確認した範囲と、未確認の範囲
5. **コミットはしない。** サンドボックスで `.git` に書き込めないため、`git add` / `git commit` は使わない。ループ側が、あなたが変更・作成したファイルをコミットする。

## 守ること

- `git add` / `git commit` / `git stash` などの git の書き込み操作は使わない（ループ側が行う）。変更するのは、このタスクに必要なファイルだけにする。
- `CircuitCanvas/docs/qa/loop/` 配下、特に `verdict.json` は編集しない（QA 担当が書く）。
- QA 担当が保存した証跡（`docs/qa/*` の既存ファイル）は書き換えない。
- 仕様が不明で判断できないときは、推測で実装せず、handoff に「要確認」として書く。
- 完了したら、最後の出力に「変更したファイル一覧」と「handoff ファイルのパス」を書く。
