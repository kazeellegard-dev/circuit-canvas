# タスク: 一般的な回路記号への置き換えと、回路記号の追加（第1弾: 1端子・2端子の記号）

## 背景

ユーザーの依頼:

1. 電源・GND・抵抗・LED など、部品のシンボルを、**一般的な回路記号**に置き換える。
2. 回路記号を増やす。参考: https://start-electronics.com/electronics/elec/circuit-symbol-matome/ （記号の一覧は PDF 内にあり、本文からは取得できなかった。JIS C 0617 / IEC 60617 で一般的な記号を、下の一覧のとおり選んだ）

この第1弾は、**1端子と2端子の記号**を扱う。3端子以上（トランジスタ、FET、オペアンプ、リレー、ロジックゲート）は、ピンの配置と配線経路への影響が大きいため、第2弾（別タスク）とする。

## 現状の実装（参考）

- シンボルは `ContentView.swift` の `SymbolItem`（`title` / `icon` / `position`）。描画は `SymbolCard`（幅 150 × 高さ 64 の角丸長方形に、SF Symbols のアイコンと名前）。
- ピンは、全シンボル共通で、中心の左右 ±75pt の 2 つ（`pins(for:)`）。ピンの丸は直径 10pt。`symbol-<title>-pin-0`（左）/ `-pin-1`（右）。
- ライブラリは `library` 配列（`DC/DC`・`MCU`・`CAN`・`抵抗`・`GND`・`センサー`・`汎用ブロック`）と `icon(for:)`。配置すると、`title` に名前が入る。
- 配線の経路計算（`WireRouting`）は、シンボル本体を幅 150 × 高さ 64 の長方形として扱う。

## 要件（Codex）

- **記号の種類を表す仕組みを導入する**（例: `SymbolKind` の列挙型。ライブラリの項目、記号の描画、ピン数を持つ）。`SymbolItem` は、種類を持つ。
- **既存の挙動は維持する:** 初期データの 4 つのシンボル（`24 V → 5 V` / `Main MCU` / `CAN` / `Temperature`）は、**ブロック図型（従来の角丸長方形 + アイコン）のまま**にする。`DC/DC`・`MCU`・`CAN`・`センサー`・`汎用ブロック` も、ブロック型として残す。識別子（`symbol-<title>`、`symbol-<title>-pin-N`）、ピンの座標（±75pt）、配線の経路計算、線分ドラッグ、交差の弧、黒丸、操作ヒントは変えない。既存の UI テストの前提を壊さない。
- **一般的な回路記号（下の一覧）を、ベクター描画（`Path` / `Shape`）で描く。** SF Symbols のアイコンで代用しない。線幅は 2pt 程度、色は主色（ダークモードで見える色）。塗りつぶす部分（LED の三角、ダイオードの三角など）は、記号ごとに決める。
- 記号型のシンボルの見た目:
  - 幅 150 × 高さ 64 の枠（角丸の外枠）は、**描かない**。ピンの丸から、記号の本体まで、**引き出し線**（直線）を描く。記号の本体は、中心付近に、幅 40〜60pt 程度で描く。
  - 名前（`title`）は、記号の下に小さく表示する。
  - 選択されているときは、アクセントカラーの枠（薄い角丸）を表示する。
  - ヒットテスト・ドラッグ・ピンのタップ領域は、従来のシンボルと同じ（本体の位置をつかんでドラッグ、ピンをタップして配線）。
  - 配線の経路計算では、記号型のシンボルの本体も、従来と同じ 150 × 64 の長方形として扱う（変えない）。
- **1端子の記号**（GND・VCC）は、ピンを**左に 1 つだけ**（`-pin-0`、中心から -75pt）持つ。右のピン（`-pin-1`）は存在しない。`pins(for:)`・配線の接続判定・削除・最近傍ピンの選択・接続済みの表示・インスペクタ・接続ありの判定など、ピンを扱うすべての場所を、種類ごとのピン数に対応させる。記号は横向きに描く（引き出し線が左から入り、右へ向かって GND の 3 本線・VCC の横棒が描かれる。回転機能は、今回は対象外）。
- **ライブラリ**を拡張する。項目が多いので、横スクロールに加えて、**カテゴリ**（例: 電源、受動部品、半導体、スイッチ・保護、負荷・その他、ブロック）で分ける。配置の操作（項目を選ぶ → キャンバスをタップ）は変えない。
- 配置したシンボルの `accessibilityValue` などで、種類を、テストから確認できるようにする（例: `symbol-<title>-kind` の識別子、または `symbol-<title>` の `accessibilityLabel` に種類名を含める。既存の `symbol-<title>` の識別子は維持）。
- 既存のライブラリ項目の `抵抗` と `GND` は、記号型に置き換える。

### 追加する記号の一覧

| 種類 | 名前（`title` の既定値） | ピン | 描画（本体） |

| 受動部品 | コンデンサ | 2 | 平行な 2 本の縦線 |

## 仮定（実装で迷ったらこれに従う。違うなら handoff に「要確認」と書く）

- 回転・反転は、今回は扱わない。全記号は、左から右へ向く。GND・VCC も、横向きに描く（縦向きが普通なので、第2弾で回転を検討する）。
- 名前（`title`）は、配置時は、ライブラリの名前と同じ。同じ名前を複数置いた場合の識別子の重複は、従来どおり許容する。
- 記号の見た目の細部（寸法、線の曲がり具合）は、厳密でなくてよい。「その記号と分かる」ことを優先する。
- 記号型シンボルの本体の当たり判定・配線の回避は、150 × 64 の長方形（従来と同じ）。

## 対象外・注意

- 3 端子以上の記号（NPN/PNP トランジスタ、FET、オペアンプ、リレー、ロジックゲート、コネクタ）は、第2弾。
- 記号の回転・反転、ピンの位置の変更、部品の定数（抵抗値など）の入力は、今回は扱わない。
- 配線の削除・選択、ピンの種類（入力/出力）の判定は、今回は扱わない。
- 初期データ: シンボルは 24V→5V (120,160) / Main MCU (370,250) / CAN (620,250) / Temperature (120,390)、配線は 3 本。アプリを再起動すると初期状態に戻る。
- 実機は対象外（iPad Pro 11-inch (M5) / iOS 26.5 シミュレーターのみ）。
