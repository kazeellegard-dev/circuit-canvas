# タスク（第2弾 2A）: ブロック図型シンボルの拡大縮小（角のハンドルをドラッグ）

分担: 実装・テスト実行 = Claude、レビュー = Codex。**2B（`circuit-symbols-multi-terminal.md`）の後**に着手する。
ユーザー決定（2026-09-26）: 操作は「角のハンドルをドラッグして、自由に変更」。

## 背景

ブロック図型（初期の 4 つ + `DC/DC`・`MCU`・`CAN`・`センサー`・`汎用ブロック`）は、150 × 64 に固定され、ピンは ±75pt。iPhone では、すぐに画面がいっぱいになる。第1弾では、初期データとテストの前提を守るため、変えなかった。

## 要件

- ブロック型のシンボルは、**大きさ（幅・高さ）を持つ**。デフォルトは、今までどおり 150 × 64（初期データ・既存テストは、変わらない）。
- 選択中のブロックの、**四隅に、ハンドル（丸、タップ領域は 32pt 以上）**を表示する。ハンドルをドラッグすると、**反対側の角を固定して**、大きさが変わる。ピンは、左右の辺の中央（幅の ±半分、高さの中央）に、追従する。
- 大きさの範囲: 幅 90〜360、高さ 48〜240（仮）。範囲を超えては、変わらない。格子（24pt）へのスナップは、しない（または、ドラッグ終了時に、任意で 8pt 単位）。
- 拡大縮小しても、ブロックの**中心ではなく、固定した反対側の角が動かない**ので、位置（中心）は、変わる。ピンの座標は、新しい大きさでの位置。
- 配線: 大きさの変更中、および終了後に、接続している配線が、ピンに追従して、再計算される（引き出し・本体を通らない・手動の線分の扱いは、既存の規則）。本体の長方形（配線が避ける範囲）も、新しい大きさにする。
- ブロック内の表示（アイコンとタイトル）は、大きさが小さいときも、はみ出さない（タイトルは 1 行、はみ出すときは省略）。
- ハンドルのドラッグが、ピンのタップ・シンボルのドラッグ・キャンバスのパンを妨げない。回路記号型には、ハンドルを出さない。
- インスペクタに、「大きさ: 幅 × 高さ」を表示し、「元の大きさに戻す」ボタンを置く。
- 識別子: `symbol-<title>-size`（`accessibilityValue` が `幅,高さ`）、ハンドル `symbol-<title>-resize-tl` / `-tr` / `-bl` / `-br`、インスペクタ `inspector-reset-size`。既存の識別子は、変えない。

## 受け入れ条件

| # | 操作 → 期待する結果 | UIテスト化 |
|---|---|---|
| R1 | ブロックを選ぶと、四隅にハンドルが出る。回路記号を選んでも、出ない。 | する |
| R2 | `br` ハンドルを (+60,+40) ドラッグすると、幅 +60・高さ +40、左上が固定。`symbol-<title>-size` と、ピンの座標（左右の辺の中央）が、更新される。 | する |
| R3 | `tl` ハンドルのドラッグで、右下が固定される。 | する |
| R4 | 最小・最大を超えて、ドラッグしても、範囲内で止まる。 | する |
| R5 | 配線がつながったブロックを拡大縮小すると、配線が追従し、他のシンボルの本体の内部を通らない。 | する |
| R6 | 「元の大きさに戻す」で、150 × 64 に戻る。 | する |
| R7 | 既存テスト（ブロックの ±75・150 × 64・初期データ）が、そのまま通る。 | する（既存テスト） |
| R8 | 小さくしても、アイコン・タイトルが、はみ出さない。ダークモードでも見える。 | QA が確認（画面） |

## 仮定

- 大きさは、アプリ内の状態（`SymbolItem`）で持つ。永続化は、今のアプリに保存がないので、扱わない（再起動で初期状態）。
- ブロックの回転は、扱わない（第1弾のとおり）。
- ピンの位置は、左右の辺の中央のまま（上下の辺への移動、ピン数の変更は、扱わない）。

## 影響しそうな箇所（Claude 用のメモ）

- `CircuitSymbol.swift`: `body(at:rotation:)` と `pins(at:rotation:)` が、ブロックを 150 × 64・±75 に固定している。大きさを引数に取る形にする。
- `ContentView.swift`: `SymbolItem` に `size`、`bodies`、`pins(for:)`、`SymbolCard` の枠、ハンドルのジェスチャ、インスペクタ。
- `WireRouting.swift`: `routingBounds` の、幅・高さの前提の確認。
- テスト: ブロックの座標前提（`WireRoutingTests` の 14 か所、UI テストの 7 か所ほど）は、デフォルトが変わらないので、基本的に、そのまま。
