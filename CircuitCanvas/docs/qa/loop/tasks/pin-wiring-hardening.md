# タスク: ピン配線の受け入れ条件を満たし、UIテストで固定する

## 背景

- ピン配線は `32547df Add interactive pin wiring` で実装済み。確認記録は `CircuitCanvas/docs/qa/pin-wiring-retest-2026-09-21.md`。
- これまでの確認は、UIテスト `testWireToolConnectsTwoSymbolPins()`（Temperature 右ピン → CAN 左ピン、配線数 3→4）の正常系1本だけ。
- 重複防止・移動への追従・ズーム/パン後のピン位置・シンボル削除との組み合わせは、未確認。

## 目的

下の受け入れ条件をすべて満たす状態にする。満たさない項目があれば修正する。新機能の追加は不要。

## 要件（Codex）

- 追加の機能実装は不要。既存の実装を、受け入れ条件と照らして確認し、満たさない項目だけ修正する。
- 「UIテスト化する」と書いた項目は、UIテスト（`CircuitCanvasUITests`）を追加する。ゲートで毎回検証するため。
- ズーム・パンを含む項目は UIテスト化しなくてよい（QA の探索テストで確認する）。
- コードを直す場合の、既存挙動の維持: ドラッグしきい値 4pt、倍率 50–250%、ピンチ・パンの追従量が 1:1 であること。

## 受け入れ条件（QA がこれで判定する）

| # | 操作 → 期待する結果 | UIテスト化 |
|---|---|---|
| 1 | 配線ツールで、シンボルの左右ピンを個別にタップできる。始点ピンをタップすると、そのピンだけがアクセントカラーで強調され、ヒント「終点のピンをタップ」が表示される。 | 不要 |
| 2 | 2つ目のピンをタップすると、直交の配線が1本追加され、選択ツールに戻る。インスペクタの接続済み配線数が +1 になる。 | 既存 |
| 3 | 追加した配線の両端が、対象のピンの位置に一致している（浮いたり、別のピンにつながらない）。 | 不要 |
| 4 | すでに配線のある2ピンを、同じ順序でもう一度つなぐ操作をしても、配線が増えない。逆順（終点→始点）でも増えない。 | する |
| 5 | 始点を選んだあと、配線ツールのボタンを押し直すと、始点の選択が解除される（次のタップが新しい始点になる）。 | する |
| 6 | 追加した配線に接続されたシンボルをドラッグすると、その配線の端点がピンに追従する。 | する |
| 7 | 追加した配線に接続されたシンボルを、インスペクタから削除すると、その配線も削除される（配線数が減り、孤立した線が残らない）。 | する |
| 8 | 倍率 50% / 100% / 175% / 250% と、パン後のそれぞれで、狙ったピンをタップすると、そのピンが始点・終点として選ばれる（隣のシンボルのピンが選ばれない）。 | 不要 |
| 9 | ピンをタップしても、シンボルは動かず、キャンバス全体もパンしない。 | 不要 |

## 仕様が未定の挙動（失敗にしない。QA は観察して、レポートの `notes` と `unverified` に書く）

- 始点と同じピンをもう一度タップしたとき（現状のコードは無視する）。
- 空白のキャンバスをタップしたとき（現状は、近くのピンが選ばれることがある）。
- 同じシンボルの左ピンと右ピンをつないだとき（現状は配線が追加される）。
- シンボルの本体（ピン以外）をタップしたとき、近い方のピンが選ばれる範囲。

## 対象外・注意

- 配線の削除機能、配線の選択、ピンの種類（入力/出力）の判定は、今回は扱わない。
- 初期データ: シンボルは 24V→5V / Main MCU / CAN / Temperature の4つ、配線は3本。アプリを再起動すると初期状態に戻る。
- 実機は対象外（iPad Pro 11-inch (M5) / iOS 26.5 シミュレーターのみ）。
