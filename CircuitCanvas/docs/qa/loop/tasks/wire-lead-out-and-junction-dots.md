# タスク: ピンからの引き出しを広げる・分岐位置に黒丸を描く

## 背景

`wire-routing-and-hints` の画面確認（`CircuitCanvas/docs/qa/wire-routing-and-hints-desktop-verify-2026-09-21.md`）の観察に対する、ユーザーの判断:

1. 配線の経路が窮屈な箇所がある（例: 24V の左ピンから 24V 本体の下端に沿って回り込む配線が、本体の下端まで約 5pt しか離れていない。左へ 20pt 出て、すぐ折り返す）。→ **左のピンなら左側へ、右のピンなら右側へ、十分に引き出してから折り曲げる**。窮屈にならない程度でよい（あとでユーザーがドラッグして調整できるため、厳密でなくてよい）。
2. ピンを共有する配線が合流すると、T 字の分岐に見える。→ **分岐する位置に、黒丸（●）を描く**。大きさは、ピンの丸と同じ。

## 現状の実装（参考）

- 経路計算は `CircuitCanvas/CircuitCanvas/WireRouting.swift` の `WireRouting.route(...)`。描画・ヒットテストは `ContentView.swift`。
- ピンの丸は `SymbolCard.pin(_:)`（直径 10pt、線幅 2pt）。ピン位置はシンボル中心の左右 ±75pt。シンボル本体は幅 150 × 高さ 64（論理座標）。
- 現状の最小の引き出しは約 20pt。折り返しの間隔も約 12pt と狭い。
- 交差の弧（ホップ）は、`WireRouting.crossings` で計算している。

## 要件（Codex）

- **既存の挙動は維持する:** 操作ヒントの固定、同じシンボルの左右ピンの接続禁止、経路がシンボル本体の内部を通らないこと、重なりの回避（ピンを共有しない配線）、線分ドラッグ、交差の弧、`wire-N` の `accessibilityValue`（`始点x,始点y,終点x,終点y`）の形式。
- **既存のテストは、経路の座標を期待値にしているものがあり、今回の変更で座標が変わる。** 変わった座標は、意図した変更として、テストの期待値を更新してよい。ただし、テストが検証している性質（本体の内部を通らない、重ならない、ドラッグで端点が離れない、など）は、弱めない。
- `xcodebuild test` を実行して、すべて成功させてから完了する。
- 黒丸の描画は、ヒットテスト（ピンのタップ、線分ドラッグ、キャンバスのパン）を妨げない。
- 黒丸の位置は、テストから確認できるようにする（例: `canvas-junctions` などの識別子の `accessibilityValue` に、座標の一覧を出す）。

## 仮定（実装で迷ったらこれに従う。違うなら handoff に「要確認」と書く）

- 黒丸の色は、配線と同じ色（黒。ダークモードでは、ラベルの主色に合わせる）。
- 分岐点は、共有するピンから見て、2 本の配線の経路が最初に分かれる点。
- 「厳密でなくてよい」ため、F1・F2 の数値は、±数 pt の誤差を許す。

## 対象外・注意

- 配線の削除、配線の選択、ピンの種類（入力/出力）の判定は、今回は扱わない。
- 経路の自動計算のアルゴリズムを、全面的に作り直す必要はない。引き出しの長さと、本体からの間隔の下限を、既存の計算に反映すればよい。
- 初期データ: シンボルは 24V→5V (120,160) / Main MCU (370,250) / CAN (620,250) / Temperature (120,390)、配線は 3 本。アプリを再起動すると初期状態に戻る。
- 実機は対象外（iPad Pro 11-inch (M5) / iOS 26.5 シミュレーターのみ）。
