# タスク（第3弾 3D）: 初回起動の使い方説明（コーチマーク）・設定からの再表示

前提: 独立して進めやすいので、3A〜3C と並行、または別枠で着手してよい。

ユーザー決定（2026-09-27）: 形式は「キャンバス上に吹き出しで説明（コーチマーク）」。次回から表示しないかの問いを、最後に出す。設定から、使い方をもう一度見られるようにする。

ユーザー決定（2026-09-29）: **初期画面は、まっさら（シンボル・メモ・配線なし）で、キャンバスの中央を表示する。** テストが既存の初期データに依存する場合は、テスト開始時にテスト回路を作図してから始める。

- 実装: 通常の起動は空・中央表示。UI テストは `makeApp()` が起動環境 `UITEST_SEED_SAMPLE=1` を渡し、アプリが起動時に従来のサンプル回路（ブロック 4 つ・付箋・配線 3 本、表示位置は左上）を作図してから始まる。
- コーチマークの 3 番目は、初期データがないため「キャンバス全体を指し、置いたシンボルを選ぶと回転・大きさ変更ができる」と説明する形に変更する。
- UI テストは、通常は `UITEST_ONBOARDING=off`（自動では出さない。保存された設定には触れない）。コーチマークのテストだけが `reset`（「次回から表示しない」を忘れて、初回起動として始める）か、指定なし（通常の起動）を使う。

## 要件

- **初回起動時**、実際の画面（初期データが置かれたキャンバス）の上に、要素を指す吹き出し（コーチマーク）を、順番に表示する。対象の候補:
  1. ライブラリ（下部のカテゴリ・シンボル一覧）— 「ここからシンボルを選んで置けます」
  2. ツールバーの「＋シンボル」「配線」「＋メモ」— 「シンボルの追加・配線・メモの追加です」
  3. シンボルをタップ選択 → 出てくる回転ボタン／拡大縮小ハンドル — 「選ぶと、回転や大きさの変更ができます」
  4. 「確認」（インスペクタ）— 「名称の変更や、接続の確認はここから」
  5. 倍率表示・ピンチ操作 — 「ピンチで拡大縮小、ドラッグで移動できます」
  - 各吹き出しに、「次へ」「スキップ」を置く。最後の吹き出しの後（または「スキップ」時）に、「次回から表示しない」の確認（チェックボックスか、はい/いいえ）を出す。
  - チェック（表示しない）を選ぶと、`UserDefaults` 等に保存し、次回以降は自動表示しない。
- **設定**から、いつでも見返せるようにする。今のツールバーに、設定（歯車アイコン）の入り口を追加し、そこに「使い方を見る」の項目を置く（同じコーチマークを、もう一度、最初から再生する）。
- コーチマークは、実際の要素の位置（画面座標）を指す必要がある。デバイスの向き・分割ビュー・ズーム状態に関わらず、正しい位置に出るようにする（初回は、初期の表示状態・倍率 100% で見せてよい。ズーム中には出さない設計でよい）。
- ダークモードでも、吹き出しが読める配色にする。

## 受け入れ条件

| # | 操作 → 期待する結果 | UIテスト化 |
|---|---|---|
| O1 | 初回起動（`UserDefaults` に記録がない状態）で、起動直後にコーチマークが始まる。 | する |
| O2 | 「次へ」で、次の吹き出しに進む。最後まで進むと、「次回から表示しない」の確認が出る。 | する |
| O3 | 「スキップ」でも、「次回から表示しない」の確認が出る。 | する |
| O4 | 「次回から表示しない」を選ぶと、アプリを再起動しても、コーチマークが自動では出ない。 | する |
| O5 | 設定の「使い方を見る」から、いつでも同じコーチマークを、最初から見られる。 | する |
| O6 | 吹き出しが、対象の要素の近くに、正しく表示される。ダークモードでも読める。 | QA が確認（見た目） |
| O7 | 通常の起動（テスト用の作図なし）で、キャンバスは空で、キャンバスの中心が表示領域の中心に来る。 | する |

## 仮定
- 設定画面は、今回、新しく作る（今はツールバーに設定の入り口がない）。中身は「使い方を見る」のみでよい（他の設定項目は、将来追加）。
- コーチマークの吹き出しの文言・対象は、上の候補をたたき台とし、実装時に、画面に合わせて微調整してよい。
