# タスク（第4弾 4D）: Undo / Redo

前提: 4C（編集モードでの削除）の後に着手する（削除も Undo の対象にするため）。

## 要件

- 画面上に Undo・Redo のアイコンを追加する。
- Undo は、シンボル・配線・付箋に対する操作（追加・移動・拡大縮小・回転・ピン追加・削除・種別/アイコン/名称の変更など）を、意味のある単位（1 回のドラッグ、1 回のボタン操作など）でひとつ戻す。手数の上限は妥当な範囲（当面 20 手）とする。
- Redo は、Undo で戻した操作を、最新まで、やり直せる。新しい操作を行うと、それ以降の Redo はできなくなる（一般的な Undo/Redo の挙動）。
- Undo・Redo が無効な状態（戻す/やり直す操作がない）のときは、アイコンをグレーアウトし、押せないようにする。無効な状態で押された場合は、ポップアップで理由を伝える（後方互換のため、押せないなら通常は発生しないが、保険として用意する）。

## 受け入れ条件（QA がこれで判定する）

1. シンボルを移動した後、Undo を押すと、元の位置に戻る。
2. Undo した後、Redo を押すと、移動後の位置に戻る。
3. 何も操作していない状態では、Undo はグレーアウトしている。
4. Undo した直後（Redo できる状態）で、新しい操作（例: 別のシンボルを移動）を行うと、Redo はグレーアウトする。
5. 20 手を超えて操作すると、最も古い操作より前には戻れない（Undo がそこで無効になる）。

## 対象外・注意

- 対象は、シンボル・配線・付箋の編集操作。ツールの選択・インスペクタ／設定の開閉・キャンバスの倍率やパンなど、見た目の一時状態は対象外。
- 実装方式（独自の履歴スタックか、SwiftUI/UndoManager か）は、実装時に決めてよい。
