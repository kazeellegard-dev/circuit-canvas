# タスク: 配線経路の改善・線分ドラッグ・操作ヒントの固定

## 背景

`pin-wiring-hardening` の確認（`CircuitCanvas/docs/qa/pin-wiring-hardening-desktop-verify-2026-09-21.md`）で、次の問題が見つかった。ユーザーが判断した内容:

- 操作ヒントが、倍率・パンに追従して、画面外へ出る（H1）。→ 直す。
- 同じシンボルの左右ピンを結ぶと、配線が本体の裏に隠れて見えない。→ **NG**（接続させない）。
- 配線が他のシンボルの本体の裏を通り、見えなくなる。→ **NG**。
- 配線どうしが重なると、つながっているように見える。→ 避けたい。
- 配線の直線部分（線分）だけをドラッグして、ずらせるようにしたい。つながっている線は追従する。

## 現状の実装（参考）

- 配線は `ContentView.swift` の `Wire`（`start` / `end`）で、経路は「始点 → 中間 x まで水平 → 垂直 → 終点」の3線分に固定されている（`middleX = (start.x + end.x) / 2`）。
- ピン位置: シンボル中心の左右 ±75pt。シンボル本体は幅 150 × 高さ 64（論理座標）。
- 操作ヒントは `canvasContent`（`scaleEffect` / `offset` の内側）の中で描画されている（191〜194 行付近）。倍率ラベルは、すでにビューポート側の `.overlay` へ移してある。

## 要件（Codex）

実装の優先順は A → B → C → D。各グループごとに、UIテスト化できるものは UIテストを追加する。

- **既存の挙動と、既存テストの前提は維持する。** 特に、`wire-N` の `accessibilityValue`（`始点x,始点y,終点x,終点y`）の形式は変えない。経路の折れ点は、別の識別子（例: `wire-N-points`）で公開する。
- 線分ドラッグのテストのため、各線分に `wire-N-segment-K` のような識別子を持つ、ヒットテスト可能な領域を置いてよい。
- ドラッグ開始しきい値 4pt、倍率 50〜250%、ピンチ・パンの 1:1 追従は変えない。
- ヒットテスト用の領域は、ピンのタップ、シンボル・付箋のドラッグ、キャンバスのパンを妨げないこと。

## 受け入れ条件（QA がこれで判定する）

### A. 操作ヒントの固定（H1）

| # | 操作 → 期待する結果 | UIテスト化 |
|---|---|---|
| A1 | 配線・付箋・シンボル配置・関連付けのヒントは、倍率 50 / 100 / 175 / 250% とパン後のすべてで、同じ大きさ・同じ位置（キャンバスの左上）に、常に表示される。 | 可能なら（ズームは `pinch`）。不要でも可 |

### B. 同じシンボルの左右ピンの接続を禁止

| # | 操作 → 期待する結果 | UIテスト化 |
|---|---|---|
| B1 | 始点に選んだピンと**同じシンボルのもう一方のピン**をタップしても、配線は追加されない。始点の選択は維持される（無視）。接続済み配線数は変わらない。 | する |

### C. 自動配線の経路

以降、「シンボル本体」は、シンボル中心を中心とする 幅 150 × 高さ 64 の長方形。「本体の内部」は、その境界を含まない内側。

| # | 操作 → 期待する結果 | UIテスト化 |
|---|---|---|
| C1 | 配線の**すべての線分**が、どのシンボルの本体の内部も通らない（始点・終点のシンボルを含む）。始点・終点のピンからは、本体の**外側へ向かって**線が出る（左ピンは左へ、右ピンは右へ）。次の 3 つの配線を、UI から作って確認する: (S1) Temperature 右 → CAN 左、(S2) Temperature 右 → Main MCU 右、(S3) 24V 左 → Main MCU 左。初期の 3 本も満たすこと。 | する |
| C2 | **ピンを共有しない**配線どうしは、同一直線上で重なる区間（長さが 0 より大きい）を持たない。**ピンを共有する**配線どうしは、共有するピンに接する線分だけ、重なってよい（分岐として）。 | する |
| C3 | シンボルをドラッグして動かしたあとも、手動で調整していない配線は、C1・C2 を満たすように経路が再計算される。手動調整済みの配線（D）は、調整した線分の位置を保つ（端点だけがピンに追従する）。 | する（C1 の範囲で） |

### D. 線分のドラッグ

「線分」は、配線の直線部分。ここでの移動対象は、**両端がピンに直接つながっていない線分**（中間の線分）とする。

| # | 操作 → 期待する結果 | UIテスト化 |
|---|---|---|
| D1 | 中間の線分をドラッグすると、線分に対して**垂直な方向だけ**に動く（水平な線分は上下だけ、垂直な線分は左右だけ）。画面上の移動量は、指の移動量と 1:1（50 / 100 / 175 / 250% のいずれでも）。 | 方向は、する。1:1 は QA が確認 |
| D2 | 移動中も、配線の両端はピンにつながったまま（離れない）。隣り合う線分は、伸び縮みして追従し、折れ点は直交のまま。 | する |
| D3 | 線分は、どのシンボル本体の内部へも移動できない（本体の境界で止まる）。 | する |
| D4 | 線分以外の場所のドラッグは、これまでどおり（キャンバスのパン、シンボル・付箋の移動）。線分のドラッグで、キャンバスはパンせず、シンボルも動かない。ドラッグ開始しきい値は 4pt。 | する |
| D5 | 手動で動かした線分の位置は、シンボルを動かしたあとも保たれる（C3）。 | する |
| D6 | 線分を動かしても、配線数と、インスペクタの接続済み配線数は変わらない。 | する |

## 仮定（実装で迷ったらこれに従う。違うなら handoff に「要確認」と書く）

- 線分ドラッグの対象は中間の線分だけ。両ピンが同じ高さにある1本の直線の配線は、今回は移動の対象外。
- 配線を「選択して強調表示」する機能は、今回は不要（ドラッグだけでよい）。
- ピンから最初に出る短い線分（ピンに接する線分）は、ドラッグの対象外。

## 対象外・注意

- 配線の削除、配線の選択、ピンの種類（入力/出力）の判定は、今回は扱わない。
- 初期データ: シンボルは 24V→5V (120,160) / Main MCU (370,250) / CAN (620,250) / Temperature (120,390)、配線は 3 本。アプリを再起動すると初期状態に戻る。
- 実機は対象外（iPad Pro 11-inch (M5) / iOS 26.5 シミュレーターのみ）。
