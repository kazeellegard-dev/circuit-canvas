# タスク: ピンチでの拡大・縮小の感度（2026-10-03 の実機フィードバック）

## 背景

iPad 第 7 世代の実機で試したところ、ピンチイン・ピンチアウトの感度が良すぎて、すぐに最大・最小に届いてしまい、使いにくかった。あわせて、ピンチをシミュレータでも確認できるようにしてほしい、という要望。

原因:
- 倍率が、指の開き具合にそのまま比例していた。範囲は 0.5〜2.5 倍と狭かった。
- 拡大・縮小の中心が、キャンバスの左上に固定されていた。指の位置が中心ではないため、目的の場所が画面からずれていき、さらにピンチを続けることになる。
- SwiftUI の MagnificationGesture は、XCUITest が合成するピンチに反応しなかった。そのため、ピンチの UI テストはスキップしていた。

## 要件

1. **感度を下げる:** 倍率は、指の距離の比を 0.6 乗した値で変える。
   - 例: 指を 2 倍に開くと、約 1.5 倍になる。
   - 1 回のピンチで、最大や最小に届きにくくする。
2. **範囲:** 25%〜250% とする。倍率メニューの選択肢（25%〜200%）を、すべて含む。
3. **指の位置を中心にする:** ピンチを始めたときに 2 本の指の間にあったキャンバス上の点を、ピンチの間ずっと指の間に保つ。
   - 指を動かすと、キャンバスもついてくる（移動も同時にできる）。
4. **ほかの操作との関係:**
   - 2 本指での移動の途中でピンチが始まったら、ピンチが引き継ぐ（移動とピンチの両方がキャンバスを動かして、ずれることがないように）。
   - 1 本指の編集ドラッグの最中や、キャンバス上での文字の編集中は、ピンチしない。
5. **シミュレータで確認できるようにする:** UIKit の UIPinchGestureRecognizer にする。2 本指での移動と同じく、ウインドウに取り付ける。
   - XCUITest のピンチで動く。
   - 手で試すときは、Simulator で Option キーを押しながらドラッグする。

## 受け入れ条件

- P1: 指の距離が 2 倍・0.5 倍のときの倍率、範囲の上限と下限、指の位置が中心に保たれること（単体テスト: `CanvasZoomTests`）
- P2: シミュレータでピンチして、次のことを確認する（UI テスト: `testPinchZoomsGentlyAroundTheFingers`）
  - 拡大しても 2 倍に届かず、縮小しても下限に届かない。
  - 画面の中央にあったキャンバス上の点が、中央に保たれる。
- P3: これまでスキップしていた `testZoomMenuLandsExactlyOnAPresetAfterAPinchToANonPresetScale` が、実際に実行され、成功する。

## 対象外

- 慣性（指を離した後も、少し動き続ける動き）
- 範囲の端で、少し行き過ぎてから戻る動き（ラバーバンド）
