# タスク（MVP 第1段階）: 保存・開く・PDF/PNG 書き出し

根拠: `docs/release-roadmap.md` の MVP（保存・PDF/PNG・iCloud Drive・Mac ショートカット）、`docs/product-requirements.md` の US-05・US-09・データ形式・信頼性、`docs/test-plan.md` の TC-01・TC-05・TC-08。

## 実装方針（2026-09-29、Claude が決定）

- **DocumentGroup にはしない。** 起動時に文書ブラウザが出ると、「初期画面は、まっさらで、キャンバスの中央を表示」（利用者の 2026-09-29 の決定）と両立しないため。単一のウインドウのまま、ファイルを開く・保存する方式にする。
  - 開く・保存の場所は、システムのファイル選択画面（Files）で選ぶ。iCloud Drive も選べる。
  - Files で `.circuitcanvas` ファイルをタップして開く（その場で開く）にも対応する。
- **独自形式**は、バージョン付きの JSON にする。
  - UTType は `com.kazeellegard.circuitcanvas.diagram`、拡張子は `.circuitcanvas`。
  - 要素の ID も保存する（グループは、メンバーを ID で指しているため）。
  - 表示位置と倍率も保存する（TC-01）。
  - 選択状態、ツール、Undo の履歴、端末ごとの設定（グリッドへのスナップ、使い方の表示）は保存しない。
- **自動保存:**
  - 保存済み（ファイルがある）キャンバスは、変更の約 1 秒後に、自動で保存する。
  - 未保存（名前のない）キャンバスは、どこにも書かない。
  - 起動時は、これまでどおり、まっさらな状態で始める。前回のファイルは、自動では開かない。
- **Mac・外部キーボード:** メニューバーに、次のショートカットを追加する。
  - 新規 ⌘N、開く ⌘O、保存 ⌘S、別名で保存 ⇧⌘S、書き出し ⌘E

## 要件

### ファイルメニュー

1. ツールバーの左端に「ファイル」メニューを置く。項目は次のとおり。
   - 新規
   - 開く…
   - 保存
   - 別名で保存…
   - 書き出す（PDF・PNG）…
2. 「保存」:
   - ファイルのあるキャンバスは、そのファイルに上書きする。
   - 未保存のキャンバスは、保存場所を尋ねる（「別名で保存」と同じ）。
3. 「新規」「開く」でキャンバスを置き換えるとき:
   - ファイルのあるキャンバスは、先に保存する。
   - 未保存の変更が残る場合は、「保存されていない変更があります」と確認する。選択肢は「保存しないで続ける」「保存…」「キャンセル」。
4. 開いた直後の状態:
   - 「新規」「開く」の後は、Undo の履歴がない状態から始まる。
   - 選択とツールは解除する。

### 読み書きの安全性（データを失わない）

5. 書き込みは、アトミックに行う（途中で失敗しても、元のファイルが残る）。
6. 読み込みに失敗したときは、理由を表示し、今のキャンバスはそのままにする。元のファイルにも書き込まない。
   - 壊れたファイル・別の形式: 「壊れているか、Circuit Canvas のファイルではありません」
   - 新しいバージョンの形式: 「アプリを更新してから開いてください」
7. ほかの端末やアプリで、ファイルが変更されていたとき（前回の読み書きから、更新日時が変わった場合）:
   - 上書きしない。
   - 自動保存を止めて、確認する。選択肢は「ファイルから読み込み直す」「上書きして保存」「別名で保存…」「キャンセル」。
8. 保存に失敗したときは、理由を表示し、自動保存を止める（失敗を繰り返して、警告を出し続けないため）。

### 書き出し（PDF・PNG）

9. 「書き出す」で、書き出しの画面を開く。
   - 選べるもの: 形式（PDF / PNG）、「実験メモを含める」（US-09）
   - 表示するもの: プレビュー、ページ数と大きさ
   - 操作: 「共有…」（共有シート）、「ファイルに保存…」（Files）
10. 書き出す範囲と見た目:
    - 範囲は、描かれているもの全体に、余白を足した矩形。キャンバス（2400×1800）の外には出さない。
    - グリッド、選択の枠、ハンドル、✗ バッジ、ヒントの文字は、含めない。
    - 常にライトモードの配色で、白い背景に描く。
11. 形式ごとの出力:
    - PDF は、描いた範囲と同じ大きさ（pt）の 1 ページ。
    - PNG は、2 倍の解像度。
12. 「実験メモを含める」をオフにすると、メモと関連付けの線を除き、範囲もそれに合わせて小さくなる。
13. 何も置かれていないキャンバスは、書き出せない（理由を表示し、保存・共有のボタンは押せない）。

## 受け入れ条件（QA がこれで判定する）

- S1: 保存して終了し、同じファイルを開くと、次のものが元どおりになる（UI テスト: `testSaveThenReopenRestoresTheWholeDiagram`）。
  - シンボル
  - 配線（保存の前に追加したものも含む）
  - メモ
- S2: ファイルのあるキャンバスは、「保存」を押さなくても、変更が自動で保存される（UI テスト: `testEditsToASavedFileAreSavedAutomatically`）。
- S3: 未保存のキャンバスで変更してから「新規」を押すと、確認が出る（UI テスト: `testNewAsksBeforeDiscardingAnUntitledDiagram`）。
  - 「キャンセル」: そのまま残る。
  - 「保存しないで続ける」: まっさらになり、Undo は押せない。
- S4: 形式の読み書き（単体テスト: `CanvasDocumentTests`）。
  - 保存して読み込むと、ID・グループ・ブロックのピン・表示位置を含めて、完全に一致する。
  - 新しいバージョンのファイル、壊れたファイルは、それぞれの理由で拒否する。
  - 読み込みに失敗しても、ファイルは変わらない。
- E1: サンプル回路を書き出すと、次のようになる（UI テスト: `testExportWritesAOnePagePDFAndA2xPNGAndHonorsTheNotesOption`）。
  - PDF は 1 ページで、キャンバス全体ではなく、回路の範囲に切り詰められている。
  - メモを除くと、ページが小さくなる。
  - PNG は、PDF の 2 倍のピクセル数になる。
- E2: 空のキャンバスは、書き出せない（UI テスト: `testExportOfABlankCanvasIsRefused`）。
- E3: 範囲の計算、ファイル名の整形、PDF・PNG の大きさ（単体テスト: `ExportTests`）。

## テストのための仕組み

- `UITEST_DOCUMENT_FILE=<名前>`:
  - アプリの一時ディレクトリにある、そのファイルを使う。起動時に、ファイルがあれば開き、なければ、そのファイルに保存するキャンバスとして始める。
  - システムのファイル選択画面は、アプリの外で動くため、UI テストでは操作しない。
- 非表示の要素 `document-state`: 値は `file=<名前|none>;unsaved=<0|1>;autosave=<on|paused>`。
- 非表示の要素 `export-summary`: 実際に書き出したデータを読み直した結果。値は `format=;pages=;width=;height=;bytes=`（空のときは `empty`）。

## 対象外（後続）

- DocumentGroup への移行、複数ウインドウ、Files の最近使った項目。
- アプリ専用の iCloud コンテナ（Files の「Circuit Canvas」フォルダ）。
- 異常終了後の、未保存キャンバスの復元。
- 次回の起動時に、前回のファイルを自動で開くこと（セキュリティスコープのブックマークが必要）。
- 用紙サイズ（A4 など）への割り付け、複数ページ、SVG。
- 「未解決」のメモだけに絞り込んでの出力（TC-14）。
- 競合の詳細な解決（NSFilePresenter による監視、バージョンの比較）。今回は、更新日時の比較で、上書きを防ぐところまで。
