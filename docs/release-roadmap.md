# Circuit Canvas リリース計画と追加提案

## フェーズ

| フェーズ | 成果 | 出荷判断 |
| --- | --- | --- |
| 0. Product Spike | 代表20シンボル、接続可能なキャンバス、実験メモ、独自ファイル形式の試作 | iPadで10分以内にサンプル図と改造メモを残せる |
| 1. MVP | 配置・配線・実験メモ・保存・PDF/PNG・iCloud Drive・Macショートカット | クローズドTestFlightへ |
| 2. v1.0 | マイシンボル、テンプレート、アクセシビリティ、70種への拡張、アプリ内ヘルプ | App Storeへ提出 |
| 3. v1.1+ | ページ、タイトル枠、注釈、CloudKit共有、SVG出力、Pro検証 | 継続率・要望に基づく |

## 実装前に必要なもの

1. **プロダクトブリーフ**: 対象ユーザー、利用場面、非目標、価値提案を1ページで固定する。本リポジトリでは`docs/market-research.md`を土台にする。
2. **情報設計・ワイヤーフレーム**: iPad横向きのキャンバス、シンボルライブラリ、インスペクタ、配線中の状態を先に決める。最小でも主要5画面を作る。
3. **デザインシステム**: 線幅、角丸、ピン形状、選択色、フォント、ダークモードを定義する。20シンボルの前に規則を固める。
4. **アーキテクチャ決定記録（ADR）**: `SwiftUI + Canvas/Core Graphics`、ファイル形式、SVG採用範囲、iCloud方式、Undo設計を文書化する。
5. **シンボルの権利・規格確認**: IEC/JIS/ANSIの図記号をどの範囲で参照・再現するか、商標・ライセンスをリリース前に確認する。
6. **App Store運用資産**: アプリアイコン、スクリーンショット、プライバシーポリシー、サポートサイト、問い合わせ導線、クラッシュ報告対応を準備する。
7. **分析方針**: アカウント不要を維持しつつ、同意に基づく匿名の利用指標（作成完了、PDF出力、継続利用）を取得するか決める。初期はクラッシュ診断のみでもよい。

## 最初の2週間で行う作業

1. 5〜8名のP0対象者に、現在の図作成フローと不満をインタビューする。
2. iPad横向きのプロトタイプで「配置→ピン接続→改造メモ→PDF出力」をテストする。
3. Xcodeプロジェクト、独自UTType、空白ドキュメント、キャンバス座標系、Undoを実装する。
4. 20シンボルのうちDC/DC、MCU、CAN、抵抗、GND、汎用ブロックを先行実装する。
5. サンプル図を3種（電源ツリー、センサー＋MCU＋CAN、モータ駆動）作り、それぞれに改造・測定メモを付けて実際にPDF出力して評価する。

## リスクと対策

| リスク | 影響 | 先回り策 |
| --- | --- | --- |
| シンボル数を増やしすぎてMVPが遅延 | 高 | 20種で利用テストし、使用頻度で70種を選ぶ |
| タッチでの配線が不正確 | 高 | 大きいヒット領域、スナップ、接続候補の強調、Apple Pencil実機テスト |
| 同期競合で図面が失われる | 高 | ローカルファイルを正とし、競合時は複製を残す。共有編集は後回し |
| 汎用図表アプリとの差別化不足 | 中 | 電気向けテンプレート、意味のある機能シンボル、最短配線を一貫して磨く |
| MacとiPadのUIが中途半端 | 中 | 画面を共通化しすぎず、同一モデルに対して入力方式ごとの最適UIを設計 |
